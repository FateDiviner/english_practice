# RAG 入门：这套知识检索到底在做什么

面向不熟悉检索增强生成的读者。技术实现与代码细节见 [RAG.md](RAG.md)，本文只讲清楚「它在解决什么问题、每一步为什么存在」。

## 一、RAG 在解决什么问题

没有 RAG 时，AI 模型的知识是**训练时塞进去的**，相当于一个闭卷考试的学生。你问「现在完成时怎么构成」，它凭记忆回答——大概率正确，但可能编。更麻烦的是，**你上传的教材笔记它一个字都不知道**。

RAG（Retrieval-Augmented Generation，检索增强生成）把考试从闭卷改成开卷：

> **先翻书，再答题。**

整个流程就是这两句话。难的地方全在「怎么翻书」。

## 二、你问一个问题后，发生了什么

以输入「现在完成时怎么构成」为例。

### 第 1 步：先判断该不该翻书

系统先看一眼问题，判断「这需要查资料吗」。

| 你输入 | 要不要查 | 原因 |
| :--- | :--- | :--- |
| `hi` | 不用 | 寒暄，直接让 AI 回应 |
| `帮我改一下这句话的语法` | 不用 | 纠错 AI 自己就会，翻书反而会被无关资料带偏 |
| `现在完成时怎么构成` | 要查 | 真的在问知识点 |

这一步叫**意图门控**。每次查资料都要花时间和调用额度，而一半以上的对话其实是闲聊与纠错，每次都翻书纯属浪费，还可能帮倒忙。

### 第 2 步：带着问题去翻书

系统拿着问题，用**三种不同的方法**同时去找资料。

### 第 3 步：把三份结果合并

三种方法找到的东西会重叠、也会各说各话，需要合并成一份。

### 第 4 步：筛掉没用的

如果三种方法都只找到毫不相关的内容，系统会**干脆不给 AI 任何资料**。

### 第 5 步：把资料编号后交给 AI

```text
[1] 来源: grammar.md #现在完成时
    现在完成时由 have 或 has 加过去分词构成，强调对现在的影响。

[2] 词库词条: abandon
    abandon /əˈbændən/
    v. 放弃，遗弃
```

并附上指令：用到了哪条就在回答里标 `[1]`；如果资料里没讲，就直说没讲，别假装讲了。

### 第 6 步：AI 照着资料回答，边生成边推送

屏幕上逐字冒出来的回复，就是这么来的。

## 三、三种翻书方法

这是整个 RAG 最核心的部分。要三种，是因为**每一种都有盲区**。

### 方法一：按字面找（BM25）

拿着问题里的关键词去**目录页**里查。

- 问题里有 `present perfect`，目录里正好有这个词 → 找到了
- 问题里有 `abandon`，词库里正好有这个词 → 找到了

**强项**：字面一模一样就一定能找到，极其精准。

**致命盲区**：用中文问「现在完成时怎么构成」，英文资料里没有这六个中文字，**一个字都匹配不上**。拿中文去查英文书的目录，当然查不到。

### 方法二：按意思找（向量）

不看字面，而是把你的问题和每段资料都**转换成一组数字**（这个过程叫 embedding）。意思相近的，数字就相近。

像一个**真正读懂了内容的助手**：

- 你问「现在完成时怎么构成」
- 它翻到一段英文写着 "The present perfect is formed with have/has + past participle"
- 字面一个字都不像，但意思对上了 → 找到了

**这是跨语言检索唯一可行的方法。** 本项目的场景是「中文提问 → 英文资料」，这条腿断了 RAG 基本没用。

**强项**：换个说法、换个语言也能找到。

**盲区**：对精确术语反而不如方法一稳。问 `present perfect` 时，它可能给出一段讲「完成时大概念」的泛泛内容。

### 方法三：顺藤摸瓜（词汇图谱）

问「abandon 的近义词」时，前两种方法可能只能找到 abandon 这个词本身，而你真正想问的是**它和别的词的关系**。

方法三专门做这件事。它知道 abandon 有这么几条关系边：

```text
近义  give up
派生  abandonment
易混  abort
```

这些关系是**在管理端「词书管理 → 词条 → 关系」里人工录入的**，不是 AI 猜出来的。

**强项**：专治「和 X 有什么区别」「有哪些搭配」这类问题——纯靠前两种方法答不好。

**盲区**：没有录关系边的词就没有输出。

## 四、三份结果怎么合并

三种方法各自给一份名单，可能重叠、可能互相矛盾。系统用的办法很朴素：**看排名投票，不看分数**。

为什么不能看分数？因为三种方法的分数根本没法比：

- 方法一给的是 BM25 分数，量纲是「关键词出现了几次、有多稀有」
- 方法二给的是余弦相似度，永远在 0 到 1 之间
- 方法三给的是固定满分

把这三种分数直接相加，就像把「米」「英尺」「公里」直接加起来——毫无意义。

所以改成**只看名次**：

```text
某段资料在方法一里排第 1，得 1/(60+1) ≈ 0.0164 分
在方法二里排第 2，得 1/(60+2) ≈ 0.0161 分
合起来约 0.0325
```

谁在多个方法里都排得靠前，谁就赢。好处是**完全不用调参数**，不必纠结「BM25 的权重该给多少」。

**这里有个大坑**：这个分数天生很小（第一名才 0.0164）。如果把「有没有价值」的及格线设成 0.15，**所有结果都会被判为不合格**，RAG 等于白接——而症状只是「好像没引用资料」，很难联想到是及格线设错了。当前及格线是 0.016，对应「至少在某一种方法里排第一」。

## 五、找不到怎么办

这是学习场景里最要命的一环。

假设问「牛顿第二定律是什么」，而知识库里全是英语语法资料——三种方法翻遍了，只找到一堆毫不相关的东西。这时有两个选择：

| 选择 | 后果 |
| :--- | :--- |
| 把搜到的塞给 AI，让它自己看着办 | AI 会**顺着这些无关内容编**，可能硬把不相干的概念扯在一起，编得还挺像回事 |
| 什么都不给，让 AI 自己答并明说资料里没有 | 你至少知道要去别处查 |

**系统选的是第二个。** 逻辑是：在学习场景里，**自信地答错，比坦白说「你的材料里没讲」危害大得多**。前者会让你记住一个错误的知识点，后者你至少知道信息有缺口。

具体做法：合并后的最高分若低于及格线 0.016，系统就把搜到的东西**全部丢弃**，一条都不注入。

## 六、找到了怎么用

资料不会直接扔给 AI，而是先做三件事。

### 1. 去重

同一段资料可能被方法一和方法二各找到一次。不去重的话，AI 会收到两份一模一样的内容，白白占掉能塞的字数额度。

### 2. 压缩

系统给注入的资料设了字数上限（3000 字）。超了就要删。

删的策略不是「从头截断」——那样经常把关键句切掉一半。而是**先找出哪句话最贴近你的问题，围绕它前后取一段**。

### 3. 编号

每段资料前标上 `[1]` `[2]`，并注明来源。然后在给 AI 的指令里写死：

> 用到哪条就在回答里标 `[n]`；资料没覆盖到就直说，**绝不假装引用说了没说的话**。

最后这条很重要：如果 AI 引用了 `[1]` 但说的内容和 `[1]` 根本对不上，你去核对时会发现张冠李戴——**比不引用更糟**。

## 七、为什么要这么多步骤

每一步拆开看都很简单，但**它们各自堵的是一个真实的失效场景**。

| 步骤 | 堵的是什么 |
| :--- | :--- |
| 意图门控 | 闲聊和纠错时乱翻书，把 AI 带偏 |
| 三种方法并行 | 中文问英文，单一方法必然失明 |
| 按名次投票 | 三种方法的分数没法直接比 |
| 及格线 | 无关内容塞进去，AI 会顺着编 |
| 去重 | 同一段资料占两次额度 |
| 压缩 | 资料太长，关键句被截断 |
| 编号引用 | AI 说的话没法核对 |

**删掉任何一步，都会有一个具体的用户场景变糟**，而且那个糟法往往很隐蔽——比如及格线设错，只会让人觉得「RAG 好像没起作用」，绝想不到是阈值的问题。

## 八、优化到底优化在哪

前面讲的都是「怎么找到」，这里讲「用起来快不快、准不准」。

### 快在哪

**默认路径一次额外的模型调用都没有。** 除了查资料本身要调一次向量接口（把问题转成数字），其余全是本地计算。

实测检索本身只要 **8~15 毫秒**。发消息后等待的那几秒，是 AI **在写回答**，不是在查资料。

那些「更聪明但要多调一次模型」的做法（比如让 AI 重新打分、重排），全做成了**开关，且默认关闭**。因为多一次调用就要多等 1~2 秒，而发消息后最烦的就是盯着空白框。

### 准在哪

三种方法互补：字面的、语义的、关系的。用中文问英文内容能命中，换个说法也能命中，问词与词的关系也能命中。

### 稳在哪

最容易被忽略的一点：**RAG 出任何问题都不能影响对话本身**。

| 情况 | 实际行为 |
| :--- | :--- |
| embedding 接口挂了 | BM25 与图谱照常工作，只是少看到一些引用 |
| 知识库是空的 | 对话照常，只是没引用 |
| 配置写错了 | 降级到最简单的模式，不会报错弹窗 |

验证时特意测过：把向量接口整个弄挂，发消息出去，**对话照常返回内容**，只是引用来源里只剩 BM25 与图谱的命中。

## 九、一句话总结

> **RAG = 先用三种方法翻你的资料 → 投票合并 → 筛掉不相关的 → 编号后交给 AI → 让 AI 照着回答并标出处。**

每一个步骤都在堵一个「AI 会答错或答偏」的具体场景。所有优化的最终目标只有一个：

> **在 2 秒内，给你一个有依据、可核对、找不到就老实说的答案。**

## 十、和你相关的两个入口

| 想做什么 | 去哪 |
| :--- | :--- |
| 上传教材笔记、语法总结 | 管理页「知识库」 |
| 看某次检索到底找到了什么、各阶段花了多久 | 管理页「检索调试」 |

「检索调试」是调阈值、增减阶段的工具——没有它，那些数字只能凭感觉改。输入一个问题就能看到三种方法各自召回了什么、合并后的排序、以及最终注入给 AI 的完整上下文。
