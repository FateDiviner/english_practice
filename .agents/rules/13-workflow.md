# AI 工作流程要求

## 动手前必须先说
每次接任务，先输出以下内容，等用户确认后再写代码：
1. 要改哪些文件、每个文件改什么
2. 关键函数的输入输出
3. 是否涉及数据库变更、是否需要迁移
4. 不确定的地方先提问

## 任务切分
- 一次只做一个原子任务，只动 1–3 个文件
- 不把建表、接口、前端、联调混在一次交付里
- 上一个任务未验收，不开始下一个

## 交付顺序
表 → 迁移 → 接口 → 测试 → 前端 → 页面验收。不允许跳过 Swagger 手动验证直接写前端。

## 测试
- 后端 service 函数必须配单元测试，尤其判分逻辑
- 测试必须真实可运行，禁止伪造通过
- 判分测试至少覆盖：大小写、首尾空格、英美拼写、宽松模式、连续正确升级、答错降级、重复提交不重复计分

## 完成后必须说明
1. 改了哪些文件
2. 对照 feature-spec 哪些验收点已满足
3. 哪些没做、为什么
4. 如何手动验证
