# 代码质量硬性要求

## 函数与文件
- 单个函数不超过 40 行，超过必须拆分
- 单个文件不超过 300 行，超过必须拆分
- 嵌套不超过 3 层，超过用提前 return 或抽函数
- 禁止出现魔法数字，阈值必须提成具名常量（如 CONSECUTIVE_CORRECT_TO_MASTER = 2）

## 命名
- 变量名必须用完整单词，禁止 d、tmp、data1、res 这类缩写
- 布尔变量以 is/has/can/should 开头
- 函数名动词开头，能一眼看出做什么

## 注释
- 每个 service 函数开头一行注释说明职责
- 判分等复杂逻辑必须注释说明规则来源（对应 feature-spec 哪条）
- 注释解释"为什么"，不复述"是什么"
- 不留 TODO 除非用户明确同意，且必须写清后续动作

## 类型与结构
- 后端所有请求/响应必须有 Pydantic schema，禁止裸 dict
- 前端组件 props 必须声明类型与默认值
- 共享逻辑抽成 composable 或 service，不复制粘贴
